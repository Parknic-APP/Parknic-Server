# 개인정보 처리방침 개정 계획 (AWS → GCP 전환)

작성일: 2026-11-23 · 상태: **초안, 사용자 결정 필요** · 개정안 전문: [`docs/legal/privacy-draft.html`](legal/privacy-draft.html)

> 이 문서는 법률 자문이 아니다. 특히 국외 이전, 위치정보 관련 의무 해당 여부는 전환 전에 전문가나 공식 안내(개인정보보호위원회, 방송통신위원회)로 한 번 확인한다.

## 1. 왜 개정하는가

현재 방침(시행일 2026-11-07)은 서버가 **AWS(호주 시드니 리전)** 에 있다고 적고 있다. GCP로 옮기면 사실과 달라진다. 방침 10항이 "방침이 바뀌면 **시행 7일 전**에 앱 또는 웹 페이지로 알린다"고 약속했으므로, **전환 날짜보다 최소 7일 먼저 고지**해야 한다.

## 4. 고지와 시행 절차 (일정 역산)

전환일을 `D`라고 하면 방침의 시행일은 `D` 이전이어야 한다(서버가 GCP로 바뀌는 날 또는 그 전).

1. **D-8 이전**: 위 결정 사항을 정한다. 개정안 HTML의 `[대괄호]` 값을 채운다.
2. **D-8 (최소 7일 전 고지)**: **현재 운영 중인 임시 서버의 `/privacy` 페이지**에 개정 예고를 게시한다. 임시 서버에 사용자가 직접 접속해서 페이지를 수정해야 한다(제가 접근할 수 없음). 아래 "예고 문구"를 페이지 상단에 넣는다. 앱 내 공지도 가능하면 함께 한다.
3. **D-day**: 이 저장소의 `src/main/resources/legal/privacy.html`을 `docs/legal/privacy-draft.html`(값을 채운 것)으로 교체하고 배포한다. 새 서버가 개정된 방침을 서빙한다.
4. 전환 후 임시 서버의 예고 문구는 제거(임시 서버를 끄면 같이 사라진다).


## 5. 방침과 실제 동작이 일치하는지 점검

방침의 문장을 코드와 운영 구성에 하나씩 대조했다. 개정안을 게시하기 **전에** ⚠️와 ❌를 해결하거나 문구를 현실에 맞춘다.

| 방침의 약속 | 실제 | 상태 |
|---|---|---|
| 위치 좌표를 서버가 저장하지 않는다 | `checkin_sessions`에 좌표 컬럼이 없고, 요청 본문을 로그에 남기지 않는다 (Caddy 접근 로그도 켜지 않음) | ✅ |
| 탈퇴 시 계정, 배지, 리뷰, 신고·차단을 삭제한다 | 사용자 행을 실제로 삭제하고 외래키 CASCADE로 연결 데이터 삭제 (`WithdrawIT`로 검증) | ✅ |
| 로그인 토큰은 서버에 해시만 보관한다 | `refresh_tokens.token_hash` | ✅ |
| 탈퇴 시 Apple 계정 연동을 해제한다 | `AppleAuthClient.revoke` 구현. **Team ID, Key ID, `.p8`을 운영 환경에 넣어야 동작**하고, Apple이 응답하지 않으면 경고만 남기고 재시도하지 않는다 | ⚠️ |
| 서버 로그는 이용자를 식별하는 용도로 쓰지 않는다 | 일부 INFO 로그에 `userId`가 찍힌다 (프로필 수정, 탈퇴, 차단, 차단 해제). 개정안은 "내부 사용자 번호가 기록될 수 있다"로 바꿨다 | ⚠️ (문구 수정 반영됨. 또는 로그에서 `userId`를 제거) |
| 로그 보관 기간 N일 | `docker-compose.prod.yaml`에 로그 로테이션 설정이 없어 컨테이너 로그가 무한히 쌓인다 | ❌ (로테이션 설정 필요) |
| 백업은 최대 N일 보관 | `backup-db.sh`의 `KEEP_DAYS` 기본값 14. Cloud Storage에 올린 백업은 **버킷 수명 주기 규칙을 따로 설정**해야 삭제된다 | ⚠️ |
| (약속하지 않음) 백업에서 복구하면 이미 탈퇴한 사용자가 되살아날 수 있다 | `restore-db.sh`는 복구 후 탈퇴를 다시 반영하지 않는다. 방침에는 쓰지 않았지만 알고 있어야 한다 | ℹ️ |
| 만 14세 미만 가입 불가 | 약관 문구뿐이고 앱/서버에서 연령을 확인하지 않는다 (Apple 로그인) | ℹ️ |
| 신고 접수 후 24시간 이내 검토 (약관 4조) | 운영 절차이고 알림 체계가 없다 | ⚠️ |

### 후속 작업 후보 (코드/설정)
1. `docker-compose.prod.yaml`에 컨테이너 로그 로테이션(`logging: driver json-file, max-size, max-file`)을 추가해서 로그 보관 기간 문구와 맞춘다.
2. `UserController`의 `userId` INFO 로그를 제거하거나 유지할지 결정한다(유지하면 방침 문구가 이미 반영됨).
3. Cloud Storage 버킷의 수명 주기 규칙(예: 14일 후 삭제)을 `docs/gcp-deploy.md`에 명령으로 추가한다.
4. 신고 접수를 운영자가 알 수 있는 방법(주기적 조회 쿼리 또는 알림)을 정한다.
